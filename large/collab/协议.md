# 协作协议

所有成员共用本协议。详细推理和执行过程留在各自的原生会话，公共文件只写结论、依据要点和位置。

## 文件与用途

| 文件 | 用途 | 何时读 |
|---|---|---|
| `PROGRESS.md` | 唯一入口：下一步、现状、生效决议、目标表、任务表、卡点、加载地图 | 每次 |
| `协议.md` | 本协议 | 处理议题、任务、决议或收工时 |
| `日志.md` | 每天的决议、任务流转和方向变化 | 收工时写；查历史时搜索 |
| `成员.md` | 成员、职能、唤醒和续接方式 | 派活、返工或验收时 |
| `运行记录/` | 派活脚本自动写入的每次派活记录，供看板读取，不手改 | 一般不读；查某次派活的结果时 |
| `决议.md` | 生效决议全文 | 任务卡引用或要改方向时 |
| `议题/I00x-*.md` | 需要多个成员分别发表观点的讨论 | 被点名时 |
| `目标/G00x-*.md` | 目标卡：要什么、总裁批准的流程（阶段、席位、人选、通过条件） | 新目标、改流程，或做 / 派属于它的任务时 |
| `任务/T00x-*.md` | 任务卡：流转、交接 | 被点名时 |
| `经验.md` | 可复用的做法和坑 | 开始同类工作前 |
| `归档/` | 已关闭的议题和任务、被取代的决议 | 查历史时，先搜索 |

## 基本规则

1. 只读加载地图要求的文件；需要历史时先搜索，再读命中部分。
2. 修改任何公共文件前重新读取它，只改属于自己的分区，不改写他人内容。
3. 讨论中的意见不是决议。只有总裁确认后写入 `决议.md` 的才是。
4. 不确定的结果写「未知」或「未验证」，不能推断为完成。
5. 不在公共文件中粘贴大段过程、日志或代码，写位置即可。
6. 路径：协作文件直接写文件名（都在 `collab/` 下）；其他项目文件，链接写 `../路径`，反引号里写相对项目根的路径。

## 写入规则

| 位置 | 谁写 | 方式 | 上限 |
|---|---|---|---|
| PROGRESS「现状」 | 完成一步的成员 | 覆盖自己相关的行 | ≤5 行，每行 ≤80 字 |
| PROGRESS「目标」表 | 总管（总裁批准后） | 一个目标一行，只写 待批准 / 进行中 / 完成 / 取消 | — |
| PROGRESS「任务」表 | 状态变化的当事人 | 同步卡头状态；「验收结论」列只由验收者写 | — |
| PROGRESS「▶ 下一步」 | 总裁，或收工时代写 | 覆盖 | 1 条 |
| PROGRESS「生效决议」 | 写决议的成员 | 每条一行 | 只列仍约束当前工作的 |
| PROGRESS「卡点 / 待你决定」 | 任何成员追加 | 解决后由解决者删除，日志记一行 | 只放未解决的 |
| `日志.md` | 收工的成员 | 新的在上，一行一条 | 每天 ≤5 条，每条 ≤60 字 |
| 议题各轮 | 对应成员 | 只追加，标明成员和轮次 | 每轮 ≤300 字 |
| 议题「裁决」 | 总裁（可代写，需总裁确认） | 填写一次 | — |
| `决议.md` | 总裁说"定了"之后 | 新增条目，不改旧条目 | — |
| 目标卡「要什么」「流程」 | 总管起草，总裁批准 | 批准后改流程见「目标与流程」，在「变更」追加一行 | — |
| 目标卡「子任务」列 | 派发人 | 新建子任务时填编号 | — |
| 任务卡「交接」 | 派发人 | 交接时填好；总裁确认后不改 | 超过 10 行的规格写进项目文档再链接 |
| 任务卡「流转」 | 经办人（见下） | 追加一行，写明接手人 | 说明 ≤60 字，证据写位置 |
| 任务卡「备注」 | 执行者或验收者 | 追加，标明日期和经办人 | 长内容写成文件放链接 |
| `成员.md` | 总裁 | 覆盖 | — |
| `经验.md` | 任何成员 | 一条一行 | ≤20 条，超出就合并 |

## 编号

- 议题 `I001`、目标 `G001`、任务 `T001`、决议 `D001`，各自递增，不复用。
- 新编号 = 在 `collab/`（含 `归档/`）中搜索到的最大编号 + 1。
- 新建议题、目标或任务：复制对应目录下的 `_模板.md`，命名为 `编号-简短主题.md`，并在 PROGRESS 对应的表加一行。

## 状态

- 议题：开放 → 第1轮 → 第2轮 → 已裁决
- 任务：已交接 → 执行中 → 待验收 → 通过 / 需补充 / 未通过；任何时候可转为「受阻：原因」。通过即结束。
- 每次变化由经办人在卡内「流转」加一行：经办人是这一步谁做的，接手人是下一步归谁。最后一行的接手人就是当前负责人，结束写「—」。改派也加一行「已交接」，写明原因。
- 同步卡头「状态」和 PROGRESS「任务」表。
- 执行者写：执行中、待验收、受阻。开始工作时先写「执行中」；不能不给结论就停止，结束时只能是「待验收」或「受阻」。
- 验收者写：通过、需补充、未通过。执行者自报完成不算通过。

## 目标与流程

- 目标由总管起草（状态「待批准」），总裁批准后改「进行中」。属于目标的任务在卡头写「目标」「阶段」，并把编号填进流程表「子任务」列。
- 阶段进度由子任务推出：某阶段的子任务全部通过，该阶段才算通过；后一阶段要等前面的阶段都通过才开始。不手写阶段状态。
- 同一席位换人：总管决定，在相关任务的流转里写明原因。
- 增删阶段、调换顺序、跳过测试或验收、改通过条件：写进「待你决定」，总裁批准后改流程表并在「变更」追加一行。
- 用派活脚本时，它会按流程表检查顺序和人选；确需偏离时加 `--override "理由"`，理由记入运行记录，看板标为偏离。
- 最后的汇报由总管把各阶段结论（验收结论用原文）写进「待你决定」，总裁批准后目标卡改「完成」并移到 `归档/目标/`。

## 独立判断

- 验收者不能是执行者本人，也不能是总管自己。独立验收时开新会话，只依据卡上的依据、目的、验收标准、授权和交付物判断，不读执行者的自我评价；验收意见由验收者本人写，总管不改写。
- 忠于目标：区分硬约束和可替换的做法；有更合适的方案就说明依据与取舍；可以反对、报告失败和不确定，不为顺从而隐藏问题。
- 议题：写第 1 轮前，只读「问题」部分，不看其他成员的观点。第 2 轮读全文并回应分歧。总裁裁决后按决议执行，保留的异议可写在下一轮或新议题中。

## 原生会话记录

流转说明末尾和决议来源中写明：`应用「会话名」日期`，例如 `Codex「T003 接口实验」10-18`。没有会话名时写能找到它的信息。

## 上报

遇到以下情况，在 PROGRESS「待你决定」追加一条，并把相关任务标为受阻：
- 超出任务卡授权范围
- 与生效决议冲突，或证据推翻了决议的前提
- 无法自行解决的阻塞

## 决议变更

决议不改原文。新决议注明「取代：D00x」，PROGRESS 中替换对应行，旧条目整段移到 `归档/决议.md`。

## 收工清单

1. `日志.md` 写今天的决议、任务流转和方向变化。
2. 更新 PROGRESS「现状」「▶ 下一步」「卡点 / 待你决定」。
3. 通过的任务：卡片移到 `归档/任务/`，从「任务」表删行，编号记入「已完成」。总裁批准完成的目标：卡片移到 `归档/目标/`，从「目标」表删行。
4. 已裁决的议题：结论写入决议，文件移到 `归档/议题/`。
5. 不再约束当前工作的决议，从「生效决议」删去（全文留在 `决议.md`）。
