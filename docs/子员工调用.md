# 子员工调用

日期：2026 年 10 月 18 日  
用途：记录 Claude 通过命令行把任务派给其他 AI 应用、取回结果并验收的固定做法。这是群聊协调层之前的最小可行方案。

## 派活脚本（推荐）

日常派活不再手敲下面的命令，改用[派活脚本](../tools/dispatch/README.md)：它按成员拼好命令、记下会话 ID、写运行记录，续接时按「任务 + 席位」自动找会话，`stop --all` 一次停下全部。下面各节保留为原始命令和验证记录。

2026-10-20 实测（经派活脚本，测试项目）：Codex、DeepSeek 新会话派活、续接、中途停止后续接改指令均通过；运行中看板每 5 秒刷新最近动作。`claude -p` 起初未登录，脚本正确记为失败；`claude auth login` 登录（Pro 订阅）后，派活、续接、中途停止后续接改指令均通过，默认型号 claude-opus-4-7；随后 `brew upgrade --cask claude-code` 升到 2.1.304，登录保留，默认型号变为 claude-opus-5-5（1M 上下文）。

## 分工

Claude 用无界面的一次性命令派活、追问、返工；用户在各应用自己的界面里回看完整过程，只看不在里面接着聊，需要插话时交给 Claude 转达。子员工交回的结果由 Claude 检查文件或 diff 后才算完成。

## DeepSeek Harness（已验证）

- 安装：`npm install -g @deepseek-ai/dsh@0.2.0-rc.2`，程序在 nvm 的 Node v24.15.0 下；升级时同样写明版本号。项目仍是开发者预览，升级前先看更新说明。
- 凭据：`~/.dsh/.env` 写一行 `DEEPSEEK_API_KEY=...`，权限 600。headless 只读环境变量和 `.env`，不读网页版里保存的 key。
- 数据：会话存于 `~/.dsh/sessions/`，按工作目录分组，与网页版共用。

在任务的工作目录里派活：

```sh
dsh headless --json "任务说明"
```

从第一行 `session` 事件取 `sessionId`，在同一目录里追问或返工：

```sh
dsh headless --json --session-id <sessionId> "追问或返工要求"
```

- 输出是逐行 JSON：`session`、`status`、`tool_call`、`tool_result`、`text`、`final`。答案在 `final.text`。
- 退出码 0 为完成，1 为中止或出错；失败原因看 `turn_end` 事件和 stderr。
- 默认权限为“工作区内修改”，派活前把工作目录选在任务需要的范围内。
- 用户运行 `dsh web`（默认 `http://127.0.0.1:3080`），在左侧工作区找到对应目录，可看到每轮的对话、工具调用和耗时轨迹。

2026-10-20 实测中途插话：后台派活后，在它执行 `sleep 40` 时终止进程，再用同一 `sessionId` 续接并改要求；它准确复述了被打断前的计划，按新要求只建了 b.txt。即"中断 + 续接"可以用来在执行中途改指令。

2026-10-18 实测：第一轮读文件并计算，第二轮用同一 `sessionId` 续接，记得上一轮结果并正确修改文件；网页版能看到两轮全过程。默认模型显示为 DeepSeek-V41-Flash。

## Codex（已验证）

- 安装：Homebrew cask，`brew upgrade --cask codex` 升级；2026-10-18 为 0.163.0。命令行版落后时无法使用新模型（0.142 调用 `gpt-6.1-sol` 被服务端拒绝），桌面版更新后命令行也要跟着升级。
- 凭据和模型：沿用 Codex 桌面版的登录和 `~/.codex/config.toml`，会话存于 `~/.codex/sessions/`。

在任务的工作目录里派活：

```sh
codex exec --json --skip-git-repo-check -s workspace-write -o last.txt "任务说明" < /dev/null
```

从第一行 `thread.started` 事件取 `thread_id`，追问或返工：

```sh
codex exec resume --json --skip-git-repo-check -c sandbox_mode='"workspace-write"' -o last.txt <thread_id> "追问或返工要求" < /dev/null
```

- 输出是逐行 JSON：`thread.started`、`turn.started`、`item.started` / `item.completed`（消息、命令、文件改动）、`turn.completed`（含 token 用量）。最终答案写入 `-o` 指定的文件。
- `resume` 不接受 `-s`，权限要用 `-c sandbox_mode=...` 指定，否则可能退回默认的只读。
- 结尾 `< /dev/null` 防止它等待标准输入。
- 不要使用 `--dangerously-bypass-approvals-and-sandbox`。

2026-10-18 实测：与 DeepSeek 同一组任务，两轮均完成，续接时记得上一轮结果并正确修改文件。单轮输入约 4.8 万 token（大部分命中缓存），明显高于 DeepSeek。用户在 Codex 桌面版能否看到这些命令行会话，尚未确认。
