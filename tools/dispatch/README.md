# 派活脚本

总管（Claude 桌面版）用它向命令行成员派活、续接、停止，并把每次派活写进项目的 `collab/运行记录/`。看板从那里读取实时进度。只用 Python 标准库；任务卡和目标卡的解析在 `tools/collab_parse.py`，与看板共用。

## 用法

在项目目录或其子目录里运行（脚本向上找 `collab/PROGRESS.md` 认项目），或加 `--project <目录>`：

```sh
python3 tools/dispatch/dispatch.py start T003 执行 codex "执行 T003：读 collab/PROGRESS.md 和 collab/任务.md 中这张卡，按卡执行。"
```

```sh
python3 tools/dispatch/dispatch.py continue T003 执行 "返工：……"
```

```sh
python3 tools/dispatch/dispatch.py stop --all
```

| 命令 | 作用 |
|---|---|
| `start <任务> <席位> <成员> <启动语>` | 开新会话派活 |
| `continue <任务> <席位> <启动语> [--run 编号]` | 续接该任务该席位最近一次的会话（或指定派活的会话）；成员沿用那一次的 |
| `stop <编号>` / `stop --all` | 停止一次 / 本项目全部正在跑的派活，状态记为「已中断」，会话保留可续接 |
| `list [--all]` | 列出派活：运行中的全部，加最近 10 条（`--all` 全部） |
| `show <编号>` | 显示一次派活的启动语、会话、token 明细、最终回复 |
| `tokens [--force]` | 从原始事件补算各次派活的 token（默认只补还没有的；新派活会自动记，一般不用） |
| `meet <议题> [--round N]` | 朝会：召集议题「与会」表里的成员开下一轮，发言原文写入议题文件（见下节） |

- 启动语写 `-` 时从标准输入读。
- 派活和续接前按任务卡和所属目标的流程表检查（见下节）；不符合时不派，退出码 2。
- 命令在成员结束时才退出，退出码 0 为完成、1 为失败、130 为被停止。总管以后台命令运行它，结束时自动被唤醒，输出末尾是最终回复。
- 成员在项目根目录运行。
- 席位是自由文字，常用「执行」「验收」。同一任务里，续接按「任务 + 席位」找会话，所以执行和验收各有各的会话。

## 流程检查

派活前读这张任务卡（`collab/任务.md` 或 `collab/任务/`，含归档）；属于目标的再读目标卡的流程表。检查：

| 情况 | 检查什么 |
|---|---|
| 零散任务（卡上没有「目标」） | 席位「执行」「验收」的成员与卡头「执行」「验收」一致 |
| 属于目标 | 目标已批准（状态「进行中」）；前面的阶段都已通过；席位是该阶段的席位或「验收」；成员与流程表「人选」和卡头一致 |
| 卡已通过或已归档 | 不再派 |
| 没有任务卡 | 不检查（临时派活） |

成员名按 `members.json` 的 `aliases` 在「人选」「执行」「验收」里认，不分大小写；写「—」或空着不检查。

不符合时列出原因并退出。确需偏离（例如流程里的人暂时用不了）就加 `--override "理由"`，理由和偏离项记入运行记录的 `override`、`deviations`，看板标为「偏离」。改流程本身（增删阶段、跳过验收等）要总裁批准，不靠 override。

## 朝会（meet）

总管先在 `collab/议题/` 复制 `_模板.md` 立题，写好「问题」（要决定什么、背景与约束、参考资料、已知选项）和「与会」（成员派活名及视角），然后：

```sh
python3 tools/dispatch/dispatch.py meet I003
```

- 每次开下一轮，最多到议题卡头「轮数上限」（不超过 3）。已有总结或裁决的议题不再开会。
- 第 1 轮：每位与会者开新会话（席位记为「朝会1」「朝会2」……，派活编号如 `I003-01`），**并行**发言；启动语只含「问题」和本人视角，彼此看不到。
- 之后各轮：续接各自的会话，启动语附上一轮全部发言，要求回应分歧、说明是否修改结论。
- 全部人结束后，脚本把发言原文写入该轮（`### 成员 · 视角 · 派活编号`），卡头状态改为「第N轮完成」。没发言成功的写明原因。中途被停止则本轮不写入。
- 每人每轮限 400 字，要求不改任何文件。
- 总管读完决定再开一轮或写「总结」；总裁写「裁决」。

## 成员

成员和命令来自**班子配置** `~/.collab-team/班子.json`（环境变量 `COLLAB_TEAM` 可改目录）：每个成员的「派活名」「别名」「事件解析」「新会话命令」「续接命令」。命令里 `{prompt}` 启动语、`{session}` 会话 ID、`{last}` 最终回复文件。改权限、模型、加成员都改班子配置，再在项目里运行 `init.sh team-sync` 刷新 `成员.md`。「可用」不是 ✓ 的成员派活时会提醒。新的事件格式要在 `dispatch.py` 的 `PARSERS` 里加解析。

没有班子配置时，用同目录的 `members.json` 作后备。

| 成员 | 应用 | 状态 |
|---|---|---|
| `codex` | `codex exec`（工作区可写） | 派活、续接、中途停止后续接均已实测 |
| `deepseek` | `dsh headless` | 同上 |
| `claude` | `claude -p`（acceptEdits） | 同上（2026-10-20 登录后实测） |

## 运行记录格式

每次派活在 `collab/运行记录/` 下留：

- `<编号>.json`：摘要，看板只读这个；
- `<编号>.jsonl`：成员输出的原始事件流；
- `<编号>.err`：标准错误（为空时删除）。

编号是「任务编号-两位序号」，如 `G003-T1-02`（旧任务如 `T003-02`）。`.json` 字段：

| 字段 | 含义 |
|---|---|
| `run` `task` `seat` `member` | 编号、任务、席位、成员 |
| `mode` | 新会话 / 续接 |
| `session` | 成员原生会话 ID |
| `continues` | 续接自哪次派活 |
| `prompt` | 启动语 |
| `status` | 运行中 / 完成 / 失败 / 已中断；看板和 `list` 发现「运行中」但进程已不在时显示为「异常结束」 |
| `started` `ended` `last_at` | 开始、结束、最近一次收到事件的时间 |
| `steps` `last_action` | 工具调用次数、最近一次动作（如“运行：pytest”） |
| `final` `error` `exit_code` | 最终回复、错误、退出码 |
| `override` `deviations` | 偏离理由、偏离项（符合流程时为空） |
| `tokens` | 这次派活的用量汇总：`input`（未走缓存的输入）、`cached`（缓存读取）、`output`、`total`、`calls`（模型调用次数）、`context`（最后一次调用的上下文大小）、`cost_usd`（Claude 命令行给出时）；Codex 另记 `session_cum`（会话累计，续接时用来扣减）。派活时边跑边算，算错只缺这一项，不影响派活 |
| `pid` `child_pid` | 脚本和成员进程号，停止时用 |

运行中每 5 秒最多写一次摘要，这就是看板上的"心跳"。记录只由脚本写，不要手改；不需要时可以整个目录删掉。
