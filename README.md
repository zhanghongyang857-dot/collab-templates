# 本地 AI 公司协作工具

把几个 AI 助手组织成一个小班子，替你推进真实项目。你定目标、拍板；Claude、Codex、DeepSeek 等助手在各自的原生应用里分工执行、互相验收，进度写进项目里的共享文件，在本机看板上一目了然。

全部是本地 Markdown 文件和 Python 标准库脚本，不需要数据库、账号或云服务。

## 为什么做

和 AI 一起做一件持续几周的事，聊天窗口很快就不够用了：

- **上下文散在聊天记录里**：换个会话、换个模型，就要重新交代一遍背景；昨天谈定的事，今天的会话不知道。
- **一个模型包办一切**：自己出方案、自己执行、自己说做完了，没有第二双眼睛。
- **你被拖进细节**：每一步都要盯着，分不清哪些事真正需要你拍板。
- **做到哪儿了说不清**：进度、卡点、花了多少 token，只能翻聊天记录。

这个工具包的做法是：**按「项目 → 目标 → 任务」组织工作，而不是按聊天组织工作**，把上下文放进项目目录里所有助手都能读写的文件，再用规则和脚本让多个模型按分工协作。

## 好处

### 1. 围绕项目、目标、任务对话，而不是围绕聊天

每个项目有一个 `collab/PROGRESS.md` 作为唯一入口，写着现状、决议和「▶ 下一步」。工作拆成三层：

- **项目**：一个目录，一份 `PROGRESS.md`。
- **目标**（`G001`）：你要的结果、成功标准，以及你批准的流程，即分几个阶段、每个阶段谁做、谁验收。
- **任务**（`G001-T1`）：一张卡写清目的、交付、授权边界、什么情况要上报，流转表记录每次交接。

任何会话开工时先读 `PROGRESS.md`，从「▶ 下一步」接着做。对话随时可以关掉，工作不会丢。

### 2. 共享的工作台上下文

协作文件都放在项目的 `collab/` 文件夹里，项目根目录只多一个 `AGENTS.md`，Claude Code 通过 `.claude/CLAUDE.md` 导入同一份。Claude、Codex、DeepSeek 打开同一个项目，看到的是同一套现状、决议和任务卡，换模型不用重新交代背景。

公共文件只写结论和位置，详细的推理和执行过程留在各自的原生会话里，需要时再回看。这些文件是纯 Markdown，可以用 git 管理，内容完全归你，也不绑定任何一家的产品。

### 3. 多模型分工协作

按席位分工，而不是让一个模型包办：

| 席位 | 谁来坐 | 做什么 |
|---|---|---|
| 总裁 | 你 | 定目标、批准框架、做重大取舍 |
| 总管 | 一个主力助手（如 Claude） | 拆目标、起草流程、派活、协调、整合成果 |
| 执行 | 按任务挑选（如 Codex、DeepSeek） | 在授权范围内自主完成任务 |
| 验收 | 总管或第三方模型 | 对照成功标准判断是否达成 |

- **用人所长**：成员表记下每个模型的档位和成本，总管按任务难度选人。
- **交叉验收**：重要目标可以交给另一个模型验收，执行者自己说做完了不算数。
- **朝会**：遇到需要讨论的问题，总管召集几个模型开会。第一轮各自独立发言、互相看不到，最多三轮，最后由你裁决，避免几个模型互相附和。

### 4. 保留原生应用的全部能力

不重写一个 agent。每个成员在自己的命令行工具里运行，比如 Claude Code、Codex CLI、DeepSeek Harness，文件、终端、搜索这些能力都照常可用。派活脚本只负责启动、续接、停止，并记录每次派活。同一个目标里尽量续接已有会话，不必每次从头开始。

### 5. 你只管需要你决定的事

总管的分析和流程框架要你明确同意后才能派活。框架内的问题由总管自己解决，只有真正卡住时才上报。需要你拍板的事统一放在「待你决定」，每条写清类型、可选方案与代价、总管建议和验收意见，你看完就能决定。

### 6. 规则由程序把关，不靠 AI 自觉

- **校验器**（`tools/check.py`）：检查卡片格式、状态是否前后一致、编号是否重复、该有的批准记录有没有。
- **派活前把关**：没有任务卡、目标还没批准、校验出错时，脚本直接拒绝派活。偏离你批准的流程时，必须写明理由，看板上会标出「偏离」。
- **每轮结束自动校验**：Claude Code 每轮结束时自动运行校验，有错误就不让这一轮结束，并要求它补全内容，不准删内容或编造批准来通过校验。

### 7. 进度一眼看清

本机常驻一个网页看板（http://127.0.0.1:3100），每次打开都从 Markdown 当场生成：

- **NOW 页**：所有项目、今天的安排、本月布局。
- **项目看板**：待你决定、目标泳道流程图（谁在哪一步）、任务状态、正在跑的派活、每次派活的用时和 token。
- **归档页**：已完成的目标和任务，同样可以看流程图和记录。

## 和直接聊天的区别

| | 直接聊天 | 本工具包 |
|---|---|---|
| 工作单位 | 一个会话 | 项目 → 目标 → 任务 |
| 上下文在哪 | 聊天记录里 | 项目里的 `collab/` 文件，所有助手共用 |
| 换会话或换模型 | 重新交代背景 | 读 `PROGRESS.md` 接着做 |
| 谁来做 | 一个模型包办 | 按席位分工，按难度和成本选人 |
| 做完了吗 | 模型自己说了算 | 对照成功标准验收，可交给第三方模型 |
| 你的角色 | 盯着每一步 | 批准框架，处理「待你决定」 |
| 规则 | 写在提示词里，靠自觉 | 校验器和派活脚本把关 |
| 进度 | 翻聊天记录 | 看板：流程图、状态、用时、token |

## 适合什么

- 持续几天到几周、需要分阶段推进的事：科研、课程项目、求职准备、写作、做工具。
- 想让多个模型分工、互相检查，而不是只用一个。
- 想把和 AI 合作的过程沉淀成可追溯、可复用的记录。

一次性的小问题直接聊天更快，不必建项目。

## 快速开始

> 目前只在 macOS 上用过；一键安装脚本和统一的 `collab` 命令还在做。

需要 Python 3（只用标准库），以及至少一个 AI 助手（Claude Code、Codex CLI 等）。

1. 克隆本仓库到固定位置，下文记为 `<仓库>`。

2. 建立 NOW 总看板，用来列出你的所有项目（数据放在 `~/Collab/`，即 `NOW.md` 和 `NOW/` 文件夹）：

   ```bash
   <仓库>/templates/init.sh now ~/Collab
   ```

3. 在要推进的项目目录里建立协作文件。项目会自动加进 NOW 的任务表；任务多、需要多人讨论时，把 `small` 换成 `large`：

   ```bash
   NOW_PATH=~/Collab/NOW.md <仓库>/templates/init.sh small
   ```

   然后让助手按 `collab/PROGRESS.md` 填好目标、截止日期和「▶ 下一步」。

4. 启动看板，打开 http://127.0.0.1:3100 ，点项目标题进项目看板：

   ```bash
   python3 <仓库>/tools/board/server.py
   ```

   想让它开机常驻，见 [tools/board/README.md](tools/board/README.md)。

5. 需要派活给命令行成员时，用派活脚本，见 [tools/dispatch/README.md](tools/dispatch/README.md)。

模板的完整用法（升级大版本、NOW 总看板、班子配置）见 [templates/README.md](templates/README.md)。

## 目录

```
templates/             协作模板：small / large 项目模板、NOW 总看板、班子示例、init.sh
tools/board            看板网页服务：NOW 页、各项目看板和归档页
tools/dispatch         派活脚本：派活、续接、停止、按流程检查、朝会、写运行记录
tools/collab_parse.py  任务卡、目标卡解析（派活脚本和看板共用）
tools/check.py         collab/ 校验：派活前、Claude 每轮结束（Stop hook）、看板顶部都用它
tools/codex-viewer     Codex 会话只读回看
```

## 当前阶段

已经能用的：项目模板、命令行派活和续接、朝会、校验和派活前把关、本机看板（含归档页）、Codex 会话回看。

还没做的：一键安装脚本、统一的 `collab` 命令和配置、示例项目、自动化测试；把各应用的原生会话接进同一个群聊的协调层，技术方案还没定。产品名称也还没定。
